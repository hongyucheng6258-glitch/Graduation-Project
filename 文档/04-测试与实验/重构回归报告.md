# 后端代码风格改造与 Sa-Token 迁移回归报告

## 1. 目标与范围

- 将 `web/backend` 的业务代码统一为黑马点评式的经典三层结构：Controller 只做转发，业务逻辑在 `IXxxService` 接口 + `XxxServiceImpl` 实现中，Controller 通过 `@Resource` 注入接口。
- 统一接口返回体为 `Result`，同时保留前端依赖的 `code`、`message` 字段。
- 将原 JWT 鉴权替换为 Sa-Token，保留学生端、管理端双账号体系与会话隔离。
- 硬约束：不改 URL、请求参数、`data` 结构、WebSocket/SSE 消息格式，不改变现有业务行为。

## 3. 结构改造说明

### 3.1 分层

- 每个业务 Service 拆为 `IXxxService` 接口与 `XxxServiceImpl` 实现；单表服务继承 MyBatis-Plus 的 `ServiceImpl<Mapper, Entity>`，跨表编排服务只实现接口。
- Controller 统一改为 `@Resource` 注入接口，去掉 `@RequiredArgsConstructor` 的构造器注入。
- 领域组件（`ChatSessionRegistry`、`DrawGuessSessionRegistry`、`DrawGuessRoomAccessPolicy`、`DrawGuessStrokePolicy`、`AdminPermissionService`、`SensitiveWordService`、定时任务等）保留原样，不为形式强行拆分。

### 3.2 返回体

- 新增 `common/Result<T>`：`success`、`errorMsg`、`data`、`total`、`code`、`message`。
- 成功固定 `code=200`、`message=success`；失败保留 `errorMsg/message`，前端 `request.js`、SSE 兜底判断无需修改。

### 3.3 Sa-Token

- 依赖：`sa-token-spring-boot3-starter`、`sa-token-redis-template`，移除 jjwt。
- 双账号：`StpKit` 提供 `STUDENT`、`ADMIN` 两个 `StpLogic`，会话互不串用。
- Token：请求头 `Authorization: Bearer <token>`，兼容既有 `?token=` 传递；有效期 7 天，会话存 Redis。
- 拦截器：`LoginInterceptor` 替代 `JwtInterceptor`，保留公开读白名单、临时密码只放行改密接口、未登录返回 HTTP 200 + `code=401` 的前端约定。
- 管理端权限：`AdminInterceptor` 校验管理员会话；禁用用户时调用 `TokenService.kickout` 清除会话。

## 4. 验证结果

### 4.1 编译与单元测试

```
mvn -B clean test
Tests run: 310, Failures: 0, Errors: 0, Skipped: 6
BUILD SUCCESS
```

6 项跳过为原有 Redis 集成测试与真实模型测试（需外部服务），非本次改造引入。

### 4.2 启动与接口冒烟

后端以 e2e 配置启动（`PLATFORM_CAPTCHA_ENABLED=false`），`/readyz` 返回 `READY`。学生端、管理端登录后冒烟通过：

- 学生：`/api/user/info`、`/api/chat/conversations`、`/api/ai/agent/capabilities`、图片上传 `/api/upload/image`、闲置/失物/动态/活动列表与详情、日程与冲突检查。
- 管理端：`/api/admin/stats/overview`、`/api/admin/user/list`、`/api/admin/notice/list`、`/api/admin/audit/pending`、AI 管理接口鉴权。
- 上传返回 `data:image/png;base64,...`，与改造前一致。

### 4.3 端到端测试

使用真实浏览器与真实 HTTP 请求执行 `tests/browser/e2e/run-all.cjs`，覆盖注册登录、审核、闲置预约、活动报名签到、失物认领、学习搭子、问答、动态、公告、通知、收藏、举报、私信、上传、AI、搜索、3D、响应式、并发等类别。

- 类别 01–14 全部通过。
- 类别 15（AI）中，会话创建、错题增删、复习记录、历史恢复、调用次数控制等 7 项通过；5 项依赖真实模型回复的用例因本机未配置 `AI_API_KEY` 失败，属环境限制。
- 类别 16 需要单独的无模型密钥后端（`E2E_AI_UNCONFIGURED_URL`），本机未启动该隔离实例，未执行；该项验证的是故障降级路径，不影响本次改造结论。
- 类别 17–20 全部通过（搜索、3D 房间、响应式布局、并发预约/报名）。
- 合计通过 145 项，失败 6 项（均为前述 AI 环境限制）。首次类别 19 因首页资源首次加载超时中断，预热后单独重跑通过。

### 4.4 Sa-Token 专项

- 学生、管理员分别登录，双端 token 互不通用。
- 重启后端容器后，改造前签发的学生与管理员 token 仍可访问受保护接口（会话存 Redis）。
- 管理员将测试账号状态置为禁用后，该账号已签发 token 立即返回 `code=401`；恢复账号后可重新登录。
- 临时密码登录仅允许访问改密接口，公开读接口匿名可访问，与改造前策略一致。

## 5. 兼容性与遗留

- 前端、WebSocket、SSE 协议未改；`Result` 同时保留新旧字段，避免前端改动。
- 配置层已移除 `JWT_SECRET` 的必填约束与生成逻辑，部署文档同步更新为 Sa-Token 说明；`.env` 中遗留的 `JWT_SECRET` 不再被读取，可在下次整理时删除。
- 部分接口文件保留了原 Service 的冗余 import，不影响编译与运行，可在后续清理中统一处理。
- AI 真实模型链路的端到端验证需在配置 `AI_API_KEY` 的环境补跑类别 15；故障降级需按 `test-16` 要求准备隔离后端。

## 6. 结论

改造后项目保持原有功能与接口契约，结构统一为 Controller → `IXxxService` → `XxxServiceImpl`，鉴权体系统一为 Sa-Token；单元测试、接口冒烟、端到端主流程与 Sa-Token 专项均通过。除本机未配置模型密钥导致的 AI 生成类用例与未启动隔离后端的故障用例之外，未发现功能回归。
