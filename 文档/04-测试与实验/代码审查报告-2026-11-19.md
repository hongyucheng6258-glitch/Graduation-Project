## 二、High

### H-1 `scripts/idea-production.sh:141` — 失败路径被 `set -e` 吞掉，恢复失败时没有可读的错误

```bash
141:                wait_ready "$backend_port" && reload_frontends
142:            fi
143:            fail 'IDEA 转发启动失败，请检查回环端口和 Docker 网络。'
```

脚本开头是 `set -euo pipefail`。这一行在"桥接容器启动失败"的分支里，用于把 Docker 后端拉回来。一旦 `wait_ready` 超时返回 1，`&&` 列表整体返回非零，`set -e` 会**立刻以状态码 1 退出**，第 143 行的 `fail` 永不会执行。

后果：

- 用户看到脚本"静默失败"，拿不到"IDEA 转发启动失败，请检查回环端口和 Docker 网络"这条关键提示；
- 后端容器已被重启，但两个前端 nginx 没有 reload，仍持有指向已销毁 bridge 的上游连接，页面 502 而没有任何日志线索。

修改方案：

```bash
            if [[ "$was_running" = true ]]; then
                docker start "$backend" >/dev/null
                if wait_ready "$backend_port"; then
                    reload_frontends
                else
                    fail 'Docker 后端恢复后未就绪，请检查容器日志；前端未 reload。'
                fi
            fi
            fail 'IDEA 转发启动失败，请检查回环端口和 Docker 网络。'
```

要点：把 `&&` 链改成显式 `if`，让失败分支可控，保证提示信息一定打印。

### M-2 图表配色不随主题切换（`chartTheme.js` + `Dashboard.vue:185-221`）

`chartPalette` 是一个静态对象，`Dashboard.vue` 只在 `onMounted(loadDashboard)` 里 `echarts.init` 一次，切换主题不会重建图表。于是暗色主题下：

- `axisLabel: chartPalette.ink2`（`#767187`）压 `--surface`（`oklch(21%)`），对比度约 **3.2:1**，12px 轴标签不达 WCAG AA（4.5:1）；
- `splitLine: chartPalette.line`（`#E8E5F0`，接近纯白）在暗底上变成高亮白网格，视觉过曝；
- `chartBase().tooltip.backgroundColor` 固定 `rgba(255,255,255,0.96)`，暗色下是白卡片。

这不是本次改动引入的（旧配色同样写死），但本次正重做视觉体系，建议一并修掉，否则暗色主题的截图会明显割裂。

修改方案（读取 CSS 变量，主题切换时重建）：

```js
// chartTheme.js
export function readChartPalette() {
  const css = getComputedStyle(document.documentElement)
  const v = (name, fallback) => (css.getPropertyValue(name).trim() || fallback)
  return {
    brand: v('--brand', '#5B4BD1'),
    accent: v('--accent', '#D89A3D'),
    success: v('--success', '#2C7A8C'),
    warning: v('--warning', '#B77A16'),
    error: v('--error', '#C0453C'),
    info: v('--info', '#7581A8'),
    ink: v('--ink', '#252233'),
    ink2: v('--ink-3', '#767187'),
    line: v('--line', '#E8E5F0'),
    tooltipBg: v('--surface', '#FFFFFF'),
  }
}
```

```js
// Dashboard.vue
const palette = ref(readChartPalette())
// 主题切换后重建：监听 data-theme 变化
const themeObserver = new MutationObserver(() => {
  palette.value = readChartPalette()
  charts.forEach(c => c.dispose())
  charts = []
  loadDashboard()
})
onMounted(() => themeObserver.observe(document.documentElement, { attributes: true, attributeFilter: ['data-theme'] }))
onBeforeUnmount(() => themeObserver.disconnect())
```

> 注意：`--brand` 在暗色主题下是 `#9B85FF`，直接替换后柱状图会更亮，需要在暗色下做一次视觉回归。

### M-3 `scripts/idea-production.sh:31-32、153-156` — `curl | grep -q` 在 `pipefail` 下的 SIGPIPE 隐患

```bash
# wait_ready
curl -fsS --max-time 2 "http://127.0.0.1:$port/readyz" 2>/dev/null |
    grep -Eq '"status"...'
```

`grep -q` 命中即退出并关闭管道，`curl` 继续写就会拿到 SIGPIPE（141）。脚本设置了 `pipefail`，整条管道会被判定失败——探测到却判定为"未就绪"。当前响应体很小、能塞进管道缓冲，所以大概率侥幸通过，但这属于典型的"偶发 40 次重试全失败"型故障。

修改方案：不要用 `-q`，或者把输出先落变量：

```bash
wait_ready() {
    local port=$1 body
    for ((attempt=0; attempt<40; attempt++)); do
        body=$(curl -fsS --max-time 2 "http://127.0.0.1:$port/readyz" 2>/dev/null || true)
        [[ "$body" =~ \"status\"[[:space:]]*:[[:space:]]*\"READY\" ]] && return 0
        sleep 1
    done
    return 1
}
```

`verify` 段的两处同理改成先取 `body` 再匹配。

另有一处耦合：`curl -fsS ... /api/admin/auth/me` 期望 `"code":401`，前提是后端用 **HTTP 200 + 业务 code 401**（`AdminInterceptor:69`、`JwtInterceptor:152` 目前确实如此）。一旦后端改成真 HTTP 401，`curl -f` 会以 22 退出，脚本直接中断。建议去掉 `-f`、改用 `-s -o /dev/stdout -w '%{http_code}'` 显式判断。

### M-4 `scripts/idea-production.sh` — 端口与项目名重复硬编码，容器缺失时无友好提示

- `write_settings` 写死 `MYSQL_PORT=23306`、`REDIS_PORT=26379`、`26333`、`21434`（第 87-91 行），bridge 的 `-p 127.0.0.1:23306:3306 ...`（第 129-130 行）又是一份。改一处忘另一处，IDEA 模式就连不上数据库。
- 第 57-59 行 `host_port "$backend" 8080/tcp` 直接执行 `docker inspect`，容器不存在时输出原始 `Error: No such object` 后退出，用户看不出是"没启动 compose"。
- 默认 `project=ai-campus-docker`（第 6 行）只在带 `docker-compose.agent.yml`（其中 `name: ai-campus-docker`）时成立；只起 `docker-compose.yml` 时实际项目名是 `ai-campus`，脚本会静默找不到容器。

修改方案：

```bash
mysql_port=23306; redis_port=26379; qdrant_port=26333; embed_port=21434

require_container() {
    docker inspect "$1" >/dev/null 2>&1 ||
        fail "找不到容器 $1。请确认已用 docker compose -f docker-compose.yml -f docker-compose.agent.yml 启动（项目名 ${CAMPUS_IDEA_PROJECT:-ai-campus-docker}）。"
}
require_container "$backend"; require_container "$student"; require_container "$admin"
```

端口在 `write_settings` 与 `docker run -p` 统一引用上述变量。

### M-5 `tests/browser/system-admin-routes.cjs:186-189` — 失败时不关闭浏览器，留下孤儿进程

```js
})().catch(error => {
  console.error(error);
  process.exit(1);      // browser 未 close
});
```

断言失败（本次改动大量调整了 UI 文案与布局，断言失败概率不低）时直接 `process.exit(1)`，Chromium 不会被 `browser.close()`，反复跑回归会堆积进程，最终影响下一次启动。

修改方案：

```js
let browser
try {
  browser = await launchBrowser({ softwareWebGL: false })
  ...
} catch (error) {
  console.error(error)
  process.exitCode = 1
} finally {
  await browser?.close()
}
```

### M-6 `AdminLayout.vue:398` — 顶栏搜索框移除了原生 outline，替代焦点环对比度不足

```css
.topbar-search input { border: 0; border-radius: 8px; outline: 0; }
.topbar-search:focus-within { border-color: var(--brand-line); box-shadow: 0 0 0 3px var(--brand-soft); }
```

`--brand-soft`（`#F0EDFC`）压在 `--surface-2`（`#F7F6FB`）上对比度约 **1.1:1**，键盘用户几乎看不出焦点在哪。WCAG 2.4.7 要求焦点指示可见。

修改方案：

```css
.topbar-search:focus-within {
  border-color: var(--brand);
  box-shadow: 0 0 0 3px color-mix(in srgb, var(--brand) 22%, transparent);
}
```

（`--brand` `#5B4BD1` 对 `#F7F6FB` 约 7:1，达标。）
