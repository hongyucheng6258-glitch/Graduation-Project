# 测试方案与用例集

本文提供后续执行的系统测试依据。除本次验证记录明确列出的项目外，下列用例均为待执行，不将“已有测试代码”视为本轮运行通过。

## 环境与角色

准备独立 Compose 项目、未占用端口和独立 MySQL／Redis 卷，至少包含学生 A、B、发布者、审核员和超级管理员。使用可丢弃的演示数据；固定活动时间、物品状态、审核配置和模型配置。不要将 E2E 的演示重置脚本指向主项目数据卷。

## 执行与记录

每条记录保存用例 ID、实际操作、输入编号、业务 code、HTTP 状态、数据库前后事实、截图或日志路径、执行时间和结论。失败写明最小复现与缺陷编号；缺少设备、模型或前置数据记为 BLOCK；没有执行记为 NOT_RUN。PASS 只用于实际结果符合预期。

并发用例需保存并发时刻、每个请求结果及最终状态。业务写入成功不仅看响应，还应检查关联记录和通知；失败请求应检查是否留下不完整状态。

## 验收建议

先完成核心业务、权限及异常流程，再执行兼容性、并发和性能实验。关键状态错误、越权及数据损坏问题应优先处理。按实际执行的用例统计通过、失败、阻塞和未运行数量；没有覆盖率工具结果时，不填写代码覆盖率百分比。

本用例集共 63 项。已经执行的 21 项 Node 测试与 17 项 HTTP 检查具有独立编号和范围，见[本次验证记录](本次验证记录.md)。
