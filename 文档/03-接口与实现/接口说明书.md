# 接口说明书

本文从当前 Controller 声明提取 187 个 HTTP 方法端点，覆盖学生业务、管理业务、资源和健康检查。参数表描述接收形式，具体权限和业务条件还需要结合 Service。

## 地址与认证

当前后端为 http://localhost:8080，学生端代理为 http://localhost:15173，管理端代理为 http://localhost:15174。学生和管理员登录分别使用 /api/auth/login 与 /api/admin/auth/login。受保护接口通常通过 Authorization: Bearer <token> 传递令牌；管理员令牌不能替代学生身份。

公开列表和详情需要同时符合 GET 方法与明确路径规则。表中的“公开入口”只表示不以登录作为必要条件，审核状态和资源可见性仍由业务控制。个人主页相关接口在当前鉴权白名单之外，按受保护入口处理。

## 请求与返回约定

普通接口使用 JSON。分页通常接收 pageNum、pageSize，实际默认值逐端点列出；分页响应 data 中为 total、pages、list。部分方法返回普通列表，不能强行套用分页格式。

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 0,
    "pages": 0,
    "list": []
  }
}
```

R 的字段是 code、message、data。业务失败多数仍可能为 HTTP 200，调用方必须检查 code；维护模式为 HTTP 503 并返回相应业务结果，依赖就绪失败的 /readyz 也返回 HTTP 503。不能仅以 HTTP 200 判断业务操作成功。SSE、CSV 和资源响应不使用普通 JSON 数据格式。

### 主要业务结果码

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数或状态不符合要求 |
| 401 | 未登录或登录过期 |
| 403 | 无权限 |
| 404 | 资源或接口不存在 |
| 429 | 频率限制 |
| 500 | 系统错误 |
| 1003 | 敏感词 |
| 1006 | AI 调用失败 |
| 1007 | 内容审核中 |
| 1008 | 扫描 PDF 无可提取文字 |
| 1009 | 重复操作 |
| 1010 | AI 未配置 |
| 1011 | 题目信息不足 |

### 参数标记说明

path 为路径变量，query 为 URL 参数，body 为 JSON 请求体，multipart 为文件表单。默认值意味着省略时由接口补充；“必传”表示接收注解未标记 optional，字段内容是否有效还需看 DTO 校验和业务规则。HttpServletRequest／Response 等框架上下文不由客户端传入。DTO 父类继承字段不在字段附录中展开。

## 常用调用示例

示例只展示结构，写入操作应在隔离环境执行；下列凭据是演示账号，不包含本机密钥。

```http
POST /api/auth/login
Content-Type: application/json

{"studentNo":"2021001","password":"admin123","captchaId":"按验证码开关填写","captchaCode":"界面验证码"}
```

```http
GET /api/activity/list?pageNum=1&pageSize=10

POST /api/activity/123/signup
Authorization: Bearer <student-token>
Content-Type: application/json

{"remark":"演示报名"}
```

```http
POST /api/ai/chat/stream
Authorization: Bearer <student-token>
Content-Type: application/json

{"question":"请解释 Java 接口","sessionId":null}
```

SSE 流式消息与错误事件应按实际前端解析逻辑处理，不能将分段内容当作普通一次性 JSON。上传图片／文件使用 multipart/form-data；活动报名和签到报表实际返回 CSV。

## WebSocket 协议说明

WebSocket 不计入上述 HTTP 方法数量。私信通过 /api/chat/ws-ticket 获取短期票据，再连接 /ws/chat?ticket=<ticket>；游戏通过 /api/draw-guess/ws-ticket 获取票据，再连接 /ws/draw-guess?ticket=<ticket>。票据通过 Redis 一次性消费，重连应重新获取合法票据。

| 协议 | 主要输入与处理 | 需要验证的边界 |
|---|---|---|
| 私信 | 会话、消息、已读及实时推送，消息类型 text／image | 会话成员、拉黑、上传资源归属、频率与幂等 |
| 游戏 | 绘画、猜词和回合事件，服务端确定画者及计时计分 | 房间归属、当前回合、坐标、点数、私密房权限 |

游戏绘画消息包含 type=draw 及 points、color、width、tool，当前单笔上限 64 点，坐标归一化。具体事件类型以对应 WebSocketHandler 和前端协议文件为准；不将两个端点的消息结构混用。
