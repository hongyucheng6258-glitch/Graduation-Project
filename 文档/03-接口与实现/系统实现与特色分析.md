# 系统实现与特色分析

本文用于定位实现代码、解释技术设计和归纳可用工程证据。个人承担的具体工作需要学生结合提交记录、开发过程和实际参与情况补充，不能仅凭文件存在推定作者贡献。

## 特点一 三维空间复用真实业务

实现重点是将空间导航与业务内容解耦。campus-data.js 管理服务信息，campus-scene.js 管理场景，CampusWorkspace.vue 复用学生端路由和组件。工作区的内存路由避免将主浏览器地址改成普通详情页，同时保留原业务中的图片、Markdown、表单、弹窗和私信跳转。

可以据此分析组件复用、状态隔离、异步生命周期和可扩展服务注册。需要补充的展示证据是：进门、房间内办理业务、返回列表保留条件、关闭后回到原房间，以及加载异常的重试过程。

## 特点二 统一 AI 网关与业务上下文

网关集中管理模型配置、提示词、消息构造和调用日志。业务层分别准备错题、候选物品、历史报名等输入，再根据场景解析模型结果。校园向导通过规则识别意图并读取数据库，将校园活动等上下文交给外部模型组织回答。

这部分适合解释接口集成、业务数据选择、提示词约束、结构化输出与异常处理。可复核证据应包含一组脱敏输入、候选集合、模型配置、原始输出、解析结果及失败样例。当前实现没有提供自主训练大模型或向量检索系统的证据。

## 特点三 状态流程与一致性处理

活动审批的父行锁与条件更新、闲置预约的条件状态更新、失物申请的父子记录处理、评价与消息的唯一约束，都提供了具体工程分析对象。

这些机制的作用范围不同：事务不自动保证所有并发语义，唯一索引也不能代替业务资格检查。资料将已看到的处理机制和需要补测的交错条件分开，便于后续用实验验证。

## 特点四 实时互动与服务端规则

私信与游戏分别维护连接入口。游戏将画者身份、回合、计时、猜词和得分交由服务端裁决；前端负责画板输入与显示。短期一次性票据将建连资格与 HTTP 登录态衔接。

可以围绕连接生命周期、重复消息、断线重连、过期事件和作品保存展开分析。现有纯协议测试覆盖部分前端数据处理，不能代替真实多客户端联机测试。

## 特点五 内容治理与权限分层

系统将学生令牌、管理员令牌和 super／audit 管理角色区分处理。管理员请求还核验账号存在、可用状态与令牌撤销时间。内容治理结合规则、AI 预审和人工复核，并通过通知和举报形成后续处理路径。

需要展示的证据包括匿名写入被拒绝、学生令牌不能进入管理员业务、审核员不能执行超管操作、发布者身份限制及内容审核前后展示变化。

## 实现边界与可改进项

| 事项 | 当前情况 | 后续工作 |
|---|---|---|
| 图片与文件 | 主要入库保存 Data URI／Base64 | 评估容量、备份和独立存储方案 |
| PDF | 提取文本后参与问答 | 为扫描件提供单独 OCR 流程需另行实现 |
| 校园向导 | 规则检索业务数据及示例静态信息 | 核验静态信息、控制上下文隐私与长度 |
| 活动状态 | 持久化与展示状态分开 | 补充时区、截止点和并发取消测试 |
| 预约完成 | 任意参与方可确认完成 | 若需求改为双向确认，需要新状态与界面流程 |
| AI 效果 | 有功能实现和调用日志 | 补充固定样本及人工评价，不能直接推断教学效果 |
| 三维性能 | 提供画质切换 | 补充真实设备帧率、内存和加载测量 |

## 第三方能力与个人工作说明方式

Spring Boot、Vue、Three.js、Tesseract.js、PDFBox 等提供基础组件，DeepSeek 提供模型推理。工程材料应具体解释自己如何组织模块、定义流程、编写业务代码、集成服务和排查问题，并保留相应源码、提交或测试证据。

引用代码时选取能解释设计的短片段，配合调用关系和状态条件说明。避免以大量代码截图替代设计分析，也不要把依赖库自身功能计为自主实现的算法。
