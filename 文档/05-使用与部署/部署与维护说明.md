# 部署与维护说明

本文提供工程交接和演示环境的启动、核对与维护流程。完整原始部署资料见[项目部署说明](../../部署说明.md)，端口和路径以当前配置为准。

## 部署输入

需要保留 web/、docker/、docker-compose.yml、.env.example 及依赖锁文件。后端构建依赖 pom.xml 和 src，前端构建依赖 package.json、package-lock.json、src 与 public。图片和 OCR 文件属于运行资源，不能按截图缓存删除。

安装支持 Compose 的 Docker 环境，首次构建需要下载镜像和依赖。原型、历史验收文件、node_modules、dist、target 不属于源码部署的必需输入，可通过构建重新生成。

## 首次配置

在 Ai-campus 或仓库克隆后的根目录执行：

```powershell
if (-not (Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
notepad .env
```

| 配置 | 要求 |
|---|---|
| MYSQL_ROOT_PASSWORD | 填写本机数据库密码，Compose 传给后端对应配置 |
| REDIS_PASSWORD | Redis 服务端和后端客户端保持相同 |
| JWT_SECRET | 至少 32 字符的随机密钥 |
| SIGNIN_SECRET | 至少 16 字符的随机密钥 |
| AI_API_KEY | AI 功能需要有效密钥，可在后台配置 |
| STUDENT_PORT、ADMIN_PORT | 模板为 15173、15174 |
| TRUSTED_ORIGINS | 包含实际前端 Origin，修改端口时同步调整 |

实际 .env 保留在本机，不公开真实密钥。已有 .env 不应直接被模板覆盖。

## 启动与验证

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

MySQL 和 Redis 就绪后启动后端，后端就绪后启动前端。第一次创建数据库空卷时运行挂载的初始化 SQL 和演示数据；这不是每次启动都执行的流程。

| 检查 | 当前地址与期望 |
|---|---|
| 学生端 | http://localhost:15173/，应返回并显示学生端页面 |
| 管理端 | http://localhost:15174/admin/，应进入管理端页面 |
| 后端存活 | http://localhost:8080/healthz，status 为 UP |
| 依赖就绪 | http://localhost:8080/readyz，HTTP 200 且 status 为 READY |
| 首页业务 | 学生端 /api/home/aggregate，业务 code 为 200 |

健康检查只能证明对应检查范围；还应进行登录与至少一条代表业务的隔离验证。不能把进程存在或启动命令退出成功当作系统全部可用。

## 日常停止和更新

```powershell
# 恢复已有环境
docker compose up -d

# 查看日志
docker compose logs --tail 100 backend

# 停止服务并保留数据卷
docker compose down

# 按修改后的源码重新构建
docker compose up -d --build
```

docker compose down -v 会删除当前项目的数据卷，属于清除数据操作。不要在需要保留记录的主环境中将它作为普通停止命令。演示数据重置 SQL 也包含清空逻辑，已有业务数据应先备份再决定如何处理。

## 数据库升级与恢复

当前 schema.sql 声明 34 张基线表，扩展和系统配置脚本使当前运行库达到 40 张表。旧库应先与数据字典核对表、列和索引，再选择实际缺少的迁移；CREATE TABLE IF NOT EXISTS 不会补齐已存在表的列。

备份时记录数据库版本、代码或镜像版本、时间和数据库名称，采用与 MySQL 版本匹配的备份工具。备份可能包含用户信息、AI 配置和文件数据，应存放在受控位置。恢复演练在独立实例和数据卷进行，核对表结构、代表记录、资源读取和业务流程后，再决定正式切换。

一次完整恢复记录至少包括：备份命令及结果、文件校验值、目标实例、恢复日志、记录数和抽样业务结果。没有实际恢复记录时，只能表述“提供备份恢复流程”，不能表述“已完成灾备验证”。

## 常见问题定位

| 问题 | 核对顺序 |
|---|---|
| 前端端口无法绑定 | 查询监听与 Windows 保留端口，调整 STUDENT_PORT／ADMIN_PORT 和可信 Origin |
| 后端无法连接 MySQL | 容器状态、数据库名称、环境变量、权限和后端日志 |
| Redis 失败 | 服务就绪、密码一致、网络及客户端超时 |
| API 返回 200 但操作失败 | 读取 JSON 的 code、message，不能只看 HTTP 状态 |
| AI 无法调用 | 有效密钥、后台配置优先级、服务地址、配额及调用日志 |
| PDF 无法问答 | 文件类型、文本提取状态、归属和上传限制 |
| 图片或文件上传失败 | 请求大小、数据库 max_allowed_packet、资源类型和日志 |
| WebSocket 失败 | /ws 代理、可信 Origin、有效一次性票据及房间／会话身份 |
| 三维房间打不开 | WebGL、资源加载、房间页面错误、后端服务和重试结果 |
| 时间显示不一致 | 数据库、JVM、序列化和浏览器的时间值与时区 |

## 交接检查

记录最终交付提交或镜像版本；确认源码、锁文件、静态资源和配置模板齐备；按新环境重新构建验证；将测试结果与对应版本关联。实际口令、密钥、个人数据和数据库备份通过单独受控方式交接，不放进公开仓库或公开截图。

本轮文档没有执行完整恢复、公网部署或全量镜像重建。当前可确认的运行检查见[本次验证记录](../04-测试与实验/本次验证记录.md)。
